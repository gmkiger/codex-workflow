## 3. Behavioral Protocols

### 3.1 Plan-First Workflow

**For any non-trivial task (>3 files, >1 hour, or multiple valid approaches):**

1. Output a `## Plan` block with `**Status: DRAFT**` at the top.
2. Include: approach, files to modify, verification steps.
3. Save the plan to `quality_reports/plans/YYYY-MM-DD_short-description.md`.
4. Wait for the user to say "proceed", "approved", or "looks good" before executing.
5. After approval, update Status to `APPROVED` in the saved plan file.
6. For complex/ambiguous tasks, ask 3–5 clarifying questions BEFORE drafting the plan.

**Skip planning only for:** single-file typos, clear one-line fixes, explicit "just do it" from the user.

### 3.2 Session Logging

- **On starting a non-trivial task:** create `quality_reports/session_logs/YYYY-MM-DD_description.md` capturing the goal, approach, and key context. Use `templates/session-log.md`.
- **During work:** append 1–3 lines whenever a design decision is made, a problem is solved, or the approach changes. Do not batch.
- **At session end:** write a brief summary of what changed and what's next.
- **Quality reports** (full merge reports) are generated only at merge time, not every commit.

### 3.3 Context Management

When approaching long multi-step tasks:

1. Save state explicitly: update the session log and the plan file before switching tasks.
2. If context is disrupted, run `bash .codex/hooks/session-init.sh` to print the active plan + last session log entry.
3. At the start of any resumed session, run session-init and read the most recent plan before touching files.
4. Key state lives on disk — plan files (`quality_reports/plans/`), session logs, and git history are authoritative. Do not rely on conversational memory alone.

### 3.4 Pre-Flight and Post-Flight Verification Discipline

**Pre-Flight (before executing a skill):**
Output a Pre-Flight Report confirming inputs were read:
- Dataset variables found / file exists / citations resolved
- Project conventions read (which rules apply)
- Task interpretation (one sentence)
- Plan outline (3–5 bullets)

If any required input is missing, STOP and surface the issue before proceeding.

**Post-Flight (after generating text with factual claims):**
For skills that produce claims about literature, citations, or numeric results
(`/lit-review`, `/review-paper`, `/research-ideation`, `/respond-to-referees`):

1. Extract all verifiable claims (citations, numbers, named entities).
2. Generate one specific verification question per claim.
3. Answer each question from the source material alone (not from the draft).
4. Flag any claim that cannot be verified as "user review recommended."
5. Correct any claim that contradicts source material.

**After editing `.tex`, `.qmd`, or `.R` files:**
Immediately note that compilation/rendering verification is required before marking the task complete. Run `bash .codex/hooks/verify-files.sh <file-path>` for a reminder.

## 4. Quality Gates

### Thresholds (advisory by default; enforced by `.git/hooks/pre-commit`)

| Score | Checkpoint | Meaning |
|-------|-----------|---------|
| 80 | Commit | Good enough to save |
| 90 | PR | Ready for deployment |
| 95 | Excellence | Aspirational |

### Deduction rubric (abridged)

| File type | Critical issue | Deduction |
|-----------|---------------|-----------|
| Any | Compilation/render failure | −100 |
| `.tex` | Undefined citation | −15; Overfull hbox >10pt: −10 |
| `.qmd` | Broken citation: −15; Equation overflow: −20 |
| `.R` | Domain-specific bug: −30; Hardcoded absolute path: −20 |
| `.R` | Missing `set.seed()`: −10 |

Run `python3 scripts/quality_score.py <file>` to get a score. The `.git/hooks/pre-commit` hook blocks commits when any staged academic file scores below 80.

### Commit workflow

1. Run quality score on changed `.tex`/`.qmd`/`.R` files.
2. Fix any score-blocking issues (or override with explicit reason in commit message).
3. Run `./scripts/check-surface-sync.sh` to verify count claims in README/guide are consistent.
4. Create a branch, stage specific files (never `git add -A`), commit with a descriptive message.
5. Create a PR via `gh pr create`, merge with `--merge`, delete the branch.

## 5. Content Invariants

These are non-negotiable. Cite by number when flagging violations.

- **INV-1: Palette sync.** Colors in `Preambles/header.tex` must match SCSS variables in `Quarto/theme-template.scss`. Run `./scripts/check-palette-sync.sh`.
- **INV-2: Beamer↔Quarto notation parity.** Every math symbol in a Beamer `.tex` must appear identically in its `.qmd` mirror. Notation drift is a critical bug.
- **INV-3: Quarto CSS override contract.** Styles that must beat Bootstrap go in `include-in-header` as raw `<style>`, not in SCSS.
- **INV-4: TikZ as SVG.** All TikZ diagrams in Quarto/HTML must be SVG (via `/extract-tikz`). Never embed `.pdf` in a `.qmd`.
- **INV-5: Single bibliography.** `Bibliography_base.bib` is the only `.bib` file. No per-lecture files.
- **INV-6: No `\pause` or overlays.** `\pause`, `\only`, `\visible`, `\onslide` are forbidden in all Beamer files. Use multiple slides for progressive builds.
- **INV-7: Max 2 colored boxes per slide.** Two `keybox`/`definitionbox`/callout environments per slide maximum.
- **INV-8: Motivation before formalism.** Every definition must be preceded by a motivating example. No unmotivated math.
- **INV-9: `set.seed()` once at top.** R scripts: one `set.seed(YYYYMMDD)` at the very top, before any stochastic code. Never inside loops or functions.
- **INV-10: Relative paths only.** No absolute paths in R scripts. All paths relative to repository root; use `file.path()`.
- **INV-11: Transparent backgrounds.** All `ggsave()` calls for Beamer figures must include `bg = "transparent"`.
- **INV-12: Project theme on all plots.** Every ggplot must use the custom project theme. No default gray backgrounds in committed figures.

### Beamer↔Quarto auto-sync (mandatory)

Every edit to a Beamer `.tex` file MUST be immediately synced to the corresponding `.qmd` file in the same task, without being asked. Workflow:
1. Fix Beamer `.tex`
2. Apply equivalent fix to `Quarto/` mirror
3. Compile Beamer (3-pass xelatex)
4. Render Quarto (`./scripts/sync_to_docs.sh LectureN`)
5. Only then report complete

**Single source of truth:** Beamer `.tex` is authoritative. Quarto `.qmd` derives from it. HTML-only decorations (`.smaller`, plotly embeds) may exist only in Quarto and should not be overwritten during sync.

## 8. Multi-Agent Protocols

### 8.1 Sequential Role-Switching (default)

Used by: `/review-paper --peer`, `/qa-quarto`, `/slide-excellence`, `/seven-pass-review`.

```
Orchestrator reads skill file → identifies required agent roles and output files
↓
Phase N: Read .codex/agents/<role>.md → adopt role → produce output → save to file
↓
Phase N+1: Read .codex/agents/<next-role>.md → adopt role → produce output → save
↓
... (continue for all phases)
↓
Return to orchestrating role → synthesize outputs → present to user
```

Each phase output is saved to disk before the next phase begins, so no phase
depends on conversational memory from a previous role.

**Max 5 critic-fixer rounds** in any loop. After 5, halt and present remaining issues.

### 8.2 CoVe Fork Pattern (subprocess — claim-verifier only)

The claim-verifier requires genuine context isolation: it must answer verification
questions WITHOUT having seen the original draft. Use the run-workflow script:

```bash
./scripts/run-workflow.sh --fork claim-verifier \
  "Claims: [claims text]" \
  "Questions: [verification questions]" \
  "Sources: [source file paths]"
```

This spawns a fresh `codex` process with only `.codex/agents/claim-verifier.md` as
instructions plus the claims+questions+sources. The original draft is never passed.

### 8.3 Orchestrator Loop Pattern

Implemented by: `/commit` (quality check), `/qa-quarto` (critic-fixer), `/review-paper --adversarial`.

```
Step 1: IMPLEMENT — execute plan steps
Step 2: VERIFY   — compile/render/check outputs; if fail → fix → re-verify (max 2 retries)
Step 3: REVIEW   — run review agents per file type
Step 4: FIX      — apply fixes (critical → major → minor)
Step 5: RE-VERIFY — confirm fixes are clean
Step 6: SCORE    — quality_score.py; score >= threshold? YES → done. NO → loop back (max 5)
```

## 9. R Code Standards (summary — full details in `scripts/AGENTS.md`)

**Reproducibility:**
- `set.seed(YYYYMMDD)` once at the top of every R script that uses randomness (INV-9)
- All `library()` calls at the top (never `require()`)
- All paths relative to repo root; `dir.create(..., recursive = TRUE)` for outputs (INV-10)

**Preferred packages:**
- Data manipulation: `tidyverse` (`dplyr`, `tidyr`, `ggplot2`, `readr`)
- Regression tables: `modelsummary` (preferred over `stargazer`)
- `[YOUR-PACKAGES]` *(add your domain-specific packages here — e.g., `fixest` for panel FE, `survival` for survival analysis)*
- Never use `require()`, never use `T`/`F` for logicals

**Figure standards:**
- `ggsave(width = W, height = H, bg = "transparent")` — explicit dimensions, transparent bg (INV-11)
- Apply custom project theme to every plot (INV-12)
- Save as both `.pdf` and `.png`
- `saveRDS()` for every computed object (regression results, summary tables, processed data)

**Numerical discipline:**
- No `==` on doubles. Use `all.equal()` or `abs(a - b) < tol`
- CDF clamping: `eps <- 1e-12; pmin(1 - eps, pmax(eps, p))` before `qnorm()`
- Pre-allocate vectors (`numeric(n)`), never grow with `c()`
- Explicit `na.rm = TRUE` or `FALSE` on `mean()`, `sd()`, `sum()`

**Script structure:**
```r
# Header: title, author, purpose, inputs, outputs
library(tidyverse); library(modelsummary)  # + [your domain packages]
set.seed(20260415)  # YYYYMMDD
dir.create("scripts/R/_outputs/...", recursive = TRUE, showWarnings = FALSE)
# 0. Setup / 1. Data / 2. Exploration / 3. Analysis / 4. Tables+Figures / 5. Export
```
